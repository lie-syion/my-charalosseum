# AEGIS

AI 심판이 굴리는 **캐릭터 대전 · 전쟁 시뮬레이터**.

캐릭터를 만들고 → 전장과 디버프를 고르고 → 전투를 텍스트로 지켜본다.
승패 판정은 전적으로 AI가 한다. 다만 아무렇게나 판정하지 않도록,
심판에게 공정성 원칙을 강하게 못 박아 두었다.

```
캐릭터 시트 ──┐
전장 환경   ──┼──▶ [AI 심판] ──▶ 라운드별 전투 서술 + 전황 STATE ──▶ 전후 총평
디버프/변수 ──┘         ▲                                    │
                        └──────── 이전 라운드 상태 누적 ◀──────┘
```

**서버가 필요 없다.** `docs/` 폴더가 곧 사이트다. 전부 브라우저 안에서 돌고,
API 키도 브라우저 밖으로 나가지 않는다.

## 사이트로 올리기 (GitHub Pages)

1. 이 폴더를 GitHub 저장소로 만들어 푸시한다.

   ```bash
   git init && git add . && git commit -m "AEGIS"
   git branch -M main
   git remote add origin https://github.com/<아이디>/<저장소>.git
   git push -u origin main
   ```

2. 저장소 → **Settings → Pages** → Source를 **`GitHub Actions`** 로 바꾼다.
   (`Deploy from a branch` 가 **아니다**)

3. 1~2분 뒤 `https://<아이디>.github.io/<저장소>/` 에서 열린다. 끝.

`.github/workflows/pages.yml` 이 `docs/` 폴더를 통째로 업로드한다.
빌드 단계도, 서버도, 환경변수도 없다. 이후 `main` 에 푸시할 때마다 자동 배포된다.

Netlify·Vercel·Cloudflare Pages는 "publish directory" 를 `docs` 로만 지정하면
똑같이 동작한다.

> **https 로 서비스해야 한다.** 멀티플레이(WebRTC)와 클립보드 기능이 http에서는
> 막힌다. GitHub Pages는 기본이 https라 신경 쓸 게 없다.

### `Deploy from a branch` 로 하다가 Jekyll 오류가 났다면

GitHub Pages의 옛 방식은 올린 폴더를 **Jekyll 블로그로 착각해서 빌드**한다.
그러면 이런 에러가 뜨고 페이지가 만들어지지 않는다.

```
Conversion error: Jekyll::Converters::Scss encountered an error while converting
'assets/css/style.scss': No such file or directory @ dir_chdir0 - /github/workspace/docs
```

**해결: Source 를 `GitHub Actions` 로 바꾸면 끝난다.** Jekyll을 아예 거치지 않는다.

굳이 `Deploy from a branch` 를 쓰겠다면 `docs/.nojekyll` 파일(빈 파일)이
저장소에 실제로 올라가 있어야 한다. 숨김 파일이라 압축을 풀고 탐색기로 복사하면
빠지기 쉽다. 이걸로 확인한다.

```bash
git ls-files docs/.nojekyll     # 아무것도 안 나오면 안 올라간 것
touch docs/.nojekyll
git add -f docs/.nojekyll && git commit -m "add .nojekyll" && git push
```

### 로컬에서 먼저 보고 싶다면

```bash
python run.py            # docs/ 를 http://127.0.0.1:8420 로 띄우고 브라우저를 연다
```

의존성 없이 파이썬 표준 라이브러리만 쓴다. (`python -m http.server -d docs` 와 같다)

## API 키는 누가 대는가

**키 없이도 들어와서 전부 둘러볼 수 있다.** 화면·설정·전투 흐름이 그대로 돌고,
서술 자리에만 자리표시자가 나온다(**체험 모드**). 실제 판정을 켜려면 키가 필요하다.

### 싱글 플레이 — 내 키

오른쪽 위 **⚙ 설정**에 [Anthropic API 키](https://console.anthropic.com/settings/keys)를
넣으면 된다. 키는 이 브라우저의 `localStorage` 에만 저장되고,
요청은 브라우저에서 Anthropic 서버로 **직접** 간다
(`anthropic-dangerous-direct-browser-access` 헤더). 중간에 거치는 서버가 없으니
키가 어디로도 새지 않고, 사이트 주인이 남의 요금을 물 일도 없다.

### 멀티 플레이 — 한 명의 키면 충분

방장이 방을 만들면 5자리 코드가 나온다. 친구는 그 코드(또는 초대 링크)로 들어온다.
브라우저끼리 **직접 연결**(WebRTC/PeerJS)되므로 여기에도 서버가 없다.

- 판정을 실제로 돌리는 사람을 **심판**이라고 부른다. 기본값은 방장.
- **참가자는 키가 없어도 된다.** 심판의 키 하나로 방 전체가 돌아간다.
- 참가자가 자기 키를 갖고 있으면 로비에서 *"내 키로 판정을 맡을 수 있음"* 을 켤 수 있고,
  방장이 **판정 담당** 드롭다운으로 심판을 넘길 수 있다. 그러면 그 사람 키로 돌아간다.

```
   방장(심판)                        참가자
   ├ 전투 설정을 정한다               ├ 자기 캐릭터를 골라 제출
   ├ API 를 호출한다                 ├ 전투를 실시간으로 같이 본다
   └ 서술을 방 전체에 중계한다  ──────▶ └ 개입을 제안할 수 있다
```

방장이 진영 A, 참가한 순서대로 진영 B·C·… 를 맡는다. 참가자가 캐릭터를 제출하면
방장의 진영 편성 화면에 자동으로 들어온다.

> 회사·학교 방화벽이나 일부 VPN에서는 P2P 연결이 막힐 수 있다. 그럴 땐 싱글로 돌리면 된다.

- 단축키: `Space`/`Enter` 다음 라운드 · `I` 개입 · `A` 자동 진행 · `Esc` 창 닫기

## 전투 형식 6종

| 형식 | 내용 |
|---|---|
| **1:1 결투** | 합 단위의 기술 교환과 심리전 |
| **팀전 (다:다)** | 매치업·연계·연쇄 붕괴가 핵심 |
| **군대 전쟁** | 캐릭터가 지휘관. 진형·보급·사기가 개입 |
| **공성전** | 공격/수비의 승리 조건이 다른 비대칭전 |
| **배틀로얄** | 3~6개 진영. 임시 동맹과 배신 |
| **연속 관문전** | 한 명이 여러 상대를 연달아. 소모가 누적 |

## 전장과 변수

전장 15종(무너진 대성당, 화산 분화구, 부유 공중섬, 협곡 병목 …)과
디버프 18종(3배 중력, 마나 고갈지대, 칠흑의 어둠, 체력 회복 불가,
보호 대상, 능력 1회 제한, 보급 차단 …)을 조합해서 고른다.
디버프는 여러 개 동시 적용이 가능하고, 직접 써넣을 수도 있다.

서술 톤도 8종(정통 판타지 / 소년만화 열혈 / 하드코어 리얼 / 느와르 /
무협 / 전사(戰史) 다큐 / 코믹 / 코스믹 호러) 중에서 고른다.

## AI 심판의 판정 원칙

전투를 AI가 전적으로 판정하되, 다음을 시스템 프롬프트로 강제한다
(`aegis/prompts.py` → 빌드하면 `docs/data.js` 로 들어간다).

1. 사용자가 만든 캐릭터라고 편들지 않는다.
2. 시트에 적히지 않은 능력·장비를 임의로 창조하지 않는다.
3. **약점과 대가는 반드시 최소 한 번 작동한다.** 대가 없는 능력 남발 금지.
4. 전력 등급은 참고치일 뿐, 상성·환경·판단 실수가 이를 뒤집을 수 있다.
5. 부상·소모·병력 손실은 라운드를 넘어 누적되며 임의로 회복되지 않는다.
6. 매 라운드 전장 조건을 최소 하나는 실제로 개입시킨다.
7. 역전에는 반드시 앞선 라운드의 복선이 있어야 한다.
8. 결착은 애매하게 두지 않는다. 승자와 사유를 명시한다.

### 라운드마다 돌아오는 전황(STATE)

AI는 매 라운드 서술 끝에 기계가 읽을 수 있는 상태 블록을 붙인다.

```json
{
  "round": 3,
  "sides": [
    {"key": "A", "integrity": 46, "morale": 60,
     "status": ["오른쪽 늑골 골절", "발도 자세 유지 불가"], "resources": "일섬 2회 소진"}
  ],
  "momentum": "B",
  "turning_point": "빗나간 발도 후의 3초",
  "judge_note": "지구력 약점이 4라운드째에 그대로 드러났다",
  "battle_over": false, "winner": null, "victory_reason": ""
}
```

이 값이 다음 라운드 프롬프트로 그대로 이어지기 때문에, 전투가
"매 라운드 새로 시작"하지 않고 실제로 누적된다. 화면에는 전투력 게이지와
**심판 노트**(왜 그렇게 판정했는지 한 줄)로 표시된다.

## 캐릭터 만들기

로스터에서 직접 입력해도 되고, 컨셉 한 줄만 주면 AI가 시트를 뽑아주는 기능도 있다.
JSON으로 내려받고 불러올 수 있어서 친구와 시트를 주고받을 수 있다.

```json
{
  "name": "카이엔",
  "title": "잿빛 검성",
  "concept": "한 번의 발도로 승부를 끝내려는 늙은 검객",
  "combat_style": "세 합 동안 관찰한 뒤 단 한 번의 발도로 급소를 노린다",
  "power_tier": "A",
  "abilities": [
    {"name": "일섬", "desc": "납도에서 뽑아 베는 한 수",
     "cost": "빗나가면 3초간 완전히 무방비"}
  ],
  "equipment": ["태도 '재'"],
  "strengths": ["압도적인 초반 결정력"],
  "weaknesses": ["지구력이 낮다", "왼쪽 시야가 좁다", "원거리 대응 불가"]
}
```

> **팁.** 재미있는 전투는 `cost`(대가)와 `weaknesses`(약점)에서 나온다.
> 여기가 비어 있으면 AI는 판정할 근거가 없어서 밋밋한 힘싸움만 쓰게 된다.
> 반대로 약점을 구체적으로 적을수록 심판이 그것을 정확히 찔러 온다.

처음 들어오면 **카이엔**(발도술사 / 초반 결정력) · **리에타**(뇌격술사 / 근접에 취약)
· **그렌달**(방패병 / 지구전형)이 자동으로 들어가 있다. 셋의 상성이 서로 물려 있어서
같은 조합이라도 전장과 디버프에 따라 결과가 갈린다.

캐릭터·전투 설정·API 키는 전부 **그 브라우저의 localStorage** 에만 있다.
사이트를 새로 배포해도 방문자의 데이터는 그대로 남는다. 반대로 다른 기기에서는
따로 만들어야 한다(JSON 내려받기/불러오기로 옮길 수 있다).

## 커스터마이징

| 하고 싶은 것 | 건드릴 곳 | 다시 빌드 |
|---|---|---|
| 전장·디버프·톤 추가 | `aegis/presets.py` | 필요 |
| 새로운 전투 형식 | `aegis/presets.py` 의 `SCALES` | 필요 |
| 심판 성향 조정 | `aegis/prompts.py` 의 `JUDGE_RULES` | 필요 |
| 샘플 캐릭터 교체 | `characters/*.json` | 필요 |
| 색·폰트 등 테마 | `docs/style.css` 맨 위 `:root` 변수 | 불필요 |
| 진영 색 | `docs/app.js` 의 `SIDE_COLORS` | 불필요 |
| 기본 모델 | `docs/engine.js` 의 `DEFAULT_MODEL` | 불필요 |

"다시 빌드"는 이것 한 줄이다.

```bash
pip install -r requirements.txt   # 처음 한 번
python build_static.py            # aegis/ 의 프리셋·규칙 → docs/data.js
```

`docs/data.js` 는 생성물이니 직접 고치지 말고 위 명령으로 다시 만들면 된다.

## 터미널 버전

사이트와 별개로, 터미널에서 도는 버전도 남아 있다. 이쪽은 키를 `.env` 에 두고 쓴다.

```bash
cp .env.example .env      # ANTHROPIC_API_KEY 를 채운다
python run.py --cli       # 메뉴 방식
python run.py --cli --demo   # 샘플 캐릭터로 즉석 전투
python run.py --cli --mock   # 키 없이 흐름만 확인
```

## 구조

```
.github/workflows/
  pages.yml            docs/ 를 GitHub Pages 로 올리는 워크플로 (Jekyll 안 거침)

docs/                  ← 사이트 (이 폴더만 올리면 배포 끝)
  .nojekyll            옛 방식(Deploy from a branch)용 Jekyll 차단 파일
  index.html           화면 구조
  style.css            미니멀 다크 테마
  data.js              build_static.py 가 만든 프리셋·심판 규칙  (생성물)
  prompts.js           프롬프트 조립
  engine.js            Anthropic 직접 호출 · 스트리밍 · STATE 파싱
  store.js             localStorage (로스터 · 설정 · API 키)
  net.js               PeerJS 멀티플레이
  app.js               화면 전환 · 위저드 · 전투 연출 · 방 로직

aegis/                 파이썬 쪽 (터미널 버전 + 프리셋 원본)
  prompts.py           심판 시스템 프롬프트  ← 규칙의 원본
  presets.py           전투 형식 · 전장 · 디버프 · 톤  ← 프리셋의 원본
  models.py  engine.py  storage.py  cli.py  ui.py
  web/serve.py         docs/ 를 로컬에서 띄우는 작은 정적 서버
characters/            샘플 캐릭터 시트 (사이트 첫 방문 시 주입)
build_static.py        aegis/ → docs/data.js
run.py                 진입점
```

## 비용에 대해

라운드마다 API 호출이 한 번 일어나고, 대화 맥락이 누적되므로 후반 라운드일수록
입력 토큰이 늘어난다. 8라운드 1:1 전투가 대략 몇십 원 수준이지만,
설정에서 최대 토큰을 크게 잡거나 장문 모드로 군대전을 돌리면 더 든다.
